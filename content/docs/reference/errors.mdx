HaloKYC uses conventional HTTP status codes with JSON error details.

| Code | Meaning | Recommended handling |
| --- | --- | --- |
| `400` | Invalid upload or request state | Show a specific correction and do not retry unchanged. |
| `401` | Missing, invalid, or revoked API key | Stop and alert the integration owner. |
| `402` | Insufficient credits during upload | Preserve the session; tell the workspace owner to add credits. |
| `403` | The credential is valid but cannot use the resource | Check workspace status, role, and key scope. |
| `404` | Resource not found in the current scope | Check the ID and workspace pairing. |
| `409` | Session or resource state conflict | Fetch current state before deciding whether to continue. |
| `413` | Capture exceeds the accepted size | Recompress or recapture the image. |
| `422` | Structured validation failed | Correct fields such as the workflow ID or callback URL. |
| `429` | Request rate is too high | Retry with exponential backoff and jitter. |
| `5xx` | Temporary service failure | Retry safe requests with capped exponential backoff. |

## Retry safety

- `GET` requests are safe to retry.
- Do not blindly retry session creation; a timeout may have occurred after HaloKYC created the session.
- Store request intent and reconcile against your user's recent sessions before creating a replacement.
- Upload retries can return `409` if the first request succeeded. Fetch the session and continue from its current state.
- Webhook receivers must be idempotent.

## User-facing language

Keep messages neutral and operational. A network failure is not a failed identity check, and a processing timeout is not a rejection.

```text
We could not check your verification status yet.
Your submission is still safe. Try again in a moment.
```
